# Лабораторная №3 — Spring Boot + Hibernate

Backend учёта студентов на Spring Boot + Hibernate/JPA: реляционная БД, пользователи, JWT, роли USER/ADMIN, валидация и документация API.

[Методичка для двух участников: файлы, объяснения и вопросы к защите](guide.md).

## Запуск в IntelliJ IDEA

Нужна JDK 17–25 и файл `.env` в корне проекта. Если `.env` уже есть, используй его. Пример настроек приведён ниже.

1. Выбери **File → Open** и открой `pom.xml` как проект.
2. Выбери установленную JDK для проекта и дождись загрузки зависимостей Maven.
3. Открой `src/main/java/ru/studentlab/students/StudentsApplication.java`.
4. Нажми зелёный треугольник рядом с методом `main` и выбери **Run**.

Рабочая папка запуска должна быть корнем проекта `web_3`, где лежат `pom.xml` и `.env`. Тогда приложение прочитает настройки и откроет вашу локальную базу. В настройках Maven используй **Bundled Maven**. Обёртка Maven Wrapper для этого способа не нужна.

В `pom.xml` указано публичное зеркало Maven Central: основной адрес при проверке возвращал 403. Отдельный сервер БД не нужен: используется файловая H2.

Запуск основного класса описан в [документации IntelliJ IDEA](https://www.jetbrains.com/help/idea/running-applications.html).

- Приложение: http://localhost:8080/
- Swagger: http://localhost:8080/swagger-ui.html
- OpenAPI: http://localhost:8080/v3/api-docs

Остановка: кнопка **Stop** в окне запуска IntelliJ IDEA.

Данные хранятся в `data/students.mv.db` и сохраняются после перезапуска. Запускай проект из одной и той же папки. Hibernate сам создаёт таблицу при первом запуске.

## Настройки

Параметры находятся в `src/main/resources/application.properties`. Свои значения указывай в `.env` в корне проекта. Файл читается автоматически; кавычки и `export` не нужны. `.env` исключён из Git.

Пример конфигурации для ТЗ хранится здесь, отдельный `.env.example` не нужен:

```properties
SERVER_PORT=8080
DB_URL=jdbc:h2:file:./data/students
DB_USERNAME=sa
DB_PASSWORD=
APP_LOG_LEVEL=INFO
JWT_SECRET=change-this-secret-key-at-least-32-characters
JWT_ACCESS_EXPIRATION=900000
JWT_REFRESH_EXPIRATION=604800000
ADMIN_USERNAME=admin
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=change-me-admin
```

При первом создании `.env` задай свой JWT_SECRET длиной минимум 32 байта и пароль администратора. Пример выше не заменяет существующие настройки.

Сервер пишет сообщения об операциях и ошибках в консоль.

## Docker

Нужен установленный и запущенный Docker. После подготовки `.env`:

```sh
docker compose up --build
```

Остановка: `docker compose down`. Данные сохраняются в томе students-data. Локальная БД из папки data в контейнер не копируется. Dockerfile собирает JAR сам; устанавливать Java/Maven на хосте для этого способа не нужно.

На текущем Mac Docker отсутствует. Проверены сборка приложения и HTTP-сценарии вне контейнера; контейнерный запуск здесь не проверен.

## Вход и роли

При запуске создаётся первый ADMIN из ADMIN_USERNAME, ADMIN_EMAIL и ADMIN_PASSWORD в `.env`. По умолчанию в примере имя — admin. Укажите свой пароль. Если администратор уже есть, его пароль обновляется из `.env`; остальные данные сохраняются.

Чтобы сменить пароль администратора, остановите приложение, измените строку `ADMIN_PASSWORD=новый-пароль` в `.env` и запустите приложение снова. Пароль — от 6 до 40 символов и не более 72 байт UTF-8. Для Docker после изменения `.env` выполните `docker compose up -d --force-recreate`. Данные студентов удалять не нужно.

Открыть приложение и войти под администратором. Регистрация на странице входа создаёт только USER. USER читает список и подробности; ADMIN также создаёт, изменяет и удаляет студентов. API проверяет права на backend.

| Метод и адрес | Действие |
|---|---|
| POST `/api/auth/register` | username, email, password → 201 |
| POST `/api/auth/login` | username, password → accessToken, refreshToken, tokenType, expiresIn |
| POST `/api/auth/refresh` | refreshToken → новая пара токенов |
| GET `/api/auth/me` | Имя и роль по access-токену |

Для студентов и me нужен заголовок `Authorization: Bearer <accessToken>`. Access действует 15 минут, refresh — 7 дней; сроки настраиваются в `.env` в миллисекундах. expiresIn в ответе указан в секундах. Frontend автоматически обновляет access один раз при 401.

Выход очищает токены вкладки; серверного списка отозванных JWT нет. Пароли хранятся как BCrypt-хеши. Ни пароль, ни его хеш в ответах не выдаются.

## Файлы проекта

Java-код находится в `src/main/java/ru/studentlab/students`:

- `model/Student.java` — запись студента в БД;
- `dto/StudentDto.java` — поля, передаваемые через API;
- `controller/StudentController.java` — HTTP-запросы;
- `service/StudentService.java` — действия над студентами;
- `service/StudentValidator.java` — проверки данных;
- `service/StudentSearch.java` — параметры поиска, сортировки и страниц;
- `repository/StudentRepository.java` — запросы к БД через Hibernate;
- `exception/` и `dto/ApiError.java` — единые ошибки;
- `StudentsApplication.java` — запуск программы.

Frontend находится в `src/main/resources/static`: старые страницы студентов, login.html, папки js, css, assets. Пользователи и защита находятся в model/User, Role, service/AuthService, JwtService, controller/AuthController, repository/UserRepository и security. Подробности — в методичке.

## API

Адрес сохранён из лабораторной №2: `/api/requests`. В URL используется ИСУ студента.

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/requests` | Список, поиск и фильтры |
| GET | `/api/requests/{isu}` | Один студент |
| POST | `/api/requests` | Создание |
| PUT | `/api/requests/{isu}` | Полная замена |
| PATCH | `/api/requests/{isu}` | Изменение отдельных полей |
| DELETE | `/api/requests/{isu}` | Удаление |
| QUERY | `/api/requests` | Фильтры в JSON, как в старом frontend |

Для тела запроса указать `Content-Type: application/json`. Пример создания:

```json
{
  "name": "Иван Иванов",
  "group": "P3220",
  "isu": 505301,
  "dorm": 8,
  "room": "101А",
  "expDate": "2027-06-01",
  "foreigner": false,
  "notes": "Тестовая запись"
}
```

Все поля, кроме `notes`, обязательны:

- ФИО — минимум два слова, русские или латинские буквы;
- группа — латинская буква и четыре цифры, первая цифра не ноль;
- ИСУ — уникальное целое число 100000–999999;
- общежитие — целое число 1–100;
- комната — 2–4 цифры и необязательная буква;
- дата — существующая дата `ГГГГ-ММ-ДД`;
- `foreigner` — true или false;
- `notes` — текст, по умолчанию пустая строка.

ИСУ и общежитие также принимаются строками из цифр. Неизвестные поля и null отклоняются.

PUT требует все обязательные поля и очищает заметку, если её не передали. PATCH меняет только присланные поля, например `{"room":"225"}`. Пустой объект не допускается. ИСУ можно изменить, если новый номер свободен.

## Поиск, сортировка и страницы

Поиск по части поля: `name`, `group`, `isu`, `dorm` (или `dormitory`), `room`, `expDate`, `notes`. Регистр букв не учитывается. `foreigner` сравнивается точно. Несколько фильтров объединяются через И. Дата фильтруется по части строки, как в прошлой лабораторной.

```text
/api/requests?name=иван&dormitory=8&foreigner=false
/api/requests?sort=isu,desc&page=0&size=10
```

`sort` — поле и asc/desc; направление по умолчанию asc. Без sort используется порядок создания.

`page` считается от 0. `size` — от 1 до 100. Если передан только page, размер равен 20; если только size, страница равна 0. Без обоих параметров возвращается весь список, как в старом API.

Ответ — массив. Общее количество находится в заголовке `X-Total-Count`, номер и размер страницы — в `X-Page` и `X-Page-Size`. Поиск и пагинация выполняются в БД.

## Ошибки и проверка

Статусы: 401 — нет действующего токена, 403 — недостаточно прав; 201 — создано, 200 — чтение/изменение, 204 — удалено, 400 — неверный JSON или параметр адреса, 422 — ошибки полей/фильтров, 404 — не найдено, 409 — занят ИСУ, 405 — неверный метод, 415 — неверный Content-Type, 500 — внутренняя ошибка.

Формат ошибки сохранён для старого frontend:

```json
{"error":{"message":"Некорректные данные студента","details":{"isu":"ИСУ должен быть от 100000 до 999999"}}}
```

Коллекция для проверки и демонстрации: `docs/students.postman_collection.json`. Импортировать в Postman, в переменных коллекции указать adminUsername и adminPassword из своего `.env`, запускать папки по порядку. Токены сохраняются автоматически. Коллекция проверяет обе роли, использует ИСУ 990001–990003 и удаляет созданных студентов в конце. Для регистрации каждый прогон получает новое имя пользователя.

Чтобы проверить хранение данных: создай студента, останови сервер, запусти снова и получи студента по ИСУ.
