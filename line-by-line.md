Это разбор десяти файлов части «Студенты» из прежней версии проекта. Для каждой из 801 строки приведены исходный код и пояснение: что строка делает, как читать её синтаксис и, где полезно, какой есть аналог в Python. Аналоги на Python нужны для понимания: это не готовый перенос приложения на Python. Spring и Hibernate выполняют часть работы за нас, поэтому у некоторых строк нет точной замены одной строкой Python.

## Сначала — как читать Java

В Python блок задают двоеточие и отступы. В Java блок задают фигурные скобки, а простые инструкции обычно заканчивают точкой с запятой:

```python
# Python: смысл проверки
if student is None:
    raise ApiException(404, "Студент не найден")
return student
```

```java
// Java: такая проверка есть в StudentService
if (student == null) {
    throw new ApiException(404, "Студент не найден");
}
return student;
```

Отступы Java-кода нужны человеку для чтения. Границы блоков компилятор определяет по скобкам. Перенос строки сам по себе не заканчивает вызов: если скобки ещё открыты, выражение продолжается ниже.

У поля экземпляра, например `public String name;`, Java сама задаёт начальное значение null, если другого значения нет. Это не аналог одной лишь аннотации `name: str` внутри Python-класса: Python такая аннотация сама значение не создаёт. У локальных переменных Java другое правило: их надо назначить перед чтением.

Python int может расти практически до ограничений памяти. Java int ограничен диапазоном −2147483648…2147483647, long — −9223372036854775808…9223372036854775807. Поэтому проверки переполнения в этом проекте имеют смысл.

Конструктор Java называется точно как класс и не имеет возвращаемого типа. Он выполняет роль, близкую к Python __init__. В Java можно написать несколько конструкторов с разными аргументами; это называется перегрузкой.

Запись `{...}` имеет разный смысл в разных местах: после if или объявления метода это блок кода; внутри параметров аннотации может быть массив; внутри кавычек — просто текст, например путь `"/{isu}"`. Скобки в тексте логов `"ИСУ {}"` — места для подстановки значений библиотекой логирования.

## Как связаны файлы

```text
HTTP-запрос
    ↓
StudentController — выбирает действие по адресу и HTTP-методу
    ↓
StudentService — выполняет действие и определяет порядок проверок
    ├─ StudentValidator — проверяет JSON создания/изменения
    ├─ StudentSearch — проверяет параметры списка
    └─ StudentRepository — читает и меняет данные через Hibernate
           ↓
        Student — сущность, отображённая на таблицу students
    ↓
StudentDto — данные ответа клиенту

При ошибке:
ApiException → GlobalExceptionHandler → ApiError → HTTP-ответ с JSON
```

Spring создаёт контроллер, сервис, валидатор и репозиторий и передаёт зависимости через конструкторы. Это удобно представить как несколько Python-объектов, заранее созданных и переданных друг другу через __init__. Здесь создание и связывание этих объектов организует Spring.

Термины: HTTP — способ обмена запросами и ответами; JSON — текстовый формат данных; API — доступные клиенту операции; DTO — объект для передачи данных; сущность — объект, соответствующий записи БД; ORM — библиотека, связывающая объекты и реляционные таблицы. JPA задаёт интерфейсы и правила ORM в Java, Hibernate реализует их, Spring организует работу приложения.

## Как читать целое действие

Пример чтения списка: `GET /api/requests?name=Иван&page=0&size=10`.

1. Контроллер получает URL-параметры в Map: примерно `{"name": "Иван", "page": "0", "size": "10"}` в Python.
2. ObjectMapper превращает Map в JsonNode. Это преобразование объектов в памяти.
3. StudentSearch проверяет параметры, сохраняет фильтр имени и настройки страницы.
4. StudentService вызывает StudentRepository.findAll.
5. Репозиторий строит условия поиска, передаёт значение отдельно как параметр, задаёт смещение 0 и лимит 10. Для имени получится поиск по шаблону `%иван%`.
6. Hibernate получает строки БД и создаёт объекты Student. Сервис делает из них StudentDto и отдельно считает полное количество совпадений.
7. Контроллер возвращает массив DTO, а общее количество и настройки страницы — в заголовках X-Total-Count, X-Page, X-Page-Size.

Пример частичного изменения: `PATCH /api/requests/505301` с телом `{"notes": "Новая заметка"}`.

1. Контроллер берёт число 505301 из пути и JSON из тела, вызывает service.update с partial=true.
2. Сервис находит Student. Если его нет, сразу выбрасывает 404.
3. Создаёт DTO со старыми полями. Это отдельный объект данных, поэтому валидатор не меняет сущность БД во время проверки.
4. Валидатор перебирает только присланные ключи, меняет notes в DTO, затем проверяет весь итоговый DTO.
5. Сервис проверяет уникальность итогового ИСУ, копирует поля DTO в сущность, вызывает сохранение и flush.
6. При успешном завершении транзакции изменения закрепляются. Ответ — StudentDto с обновлённой заметкой.

Для PUT сервис передаст валидатору null вместо старого DTO. Тогда валидатор начнёт с нового объекта, и пропущенные обязательные поля станут ошибками. Notes необязателен и при его отсутствии останется пустой строкой. Для PATCH неприсланные поля сохранятся из старого DTO. Явный JSON null валидатор не принимает даже для notes.

Пример ошибки:

```json
{
  "error": {
    "message": "Некорректные данные студента",
    "details": {
      "isu": "ИСУ должен быть от 100000 до 999999"
    }
  }
}
```

Здесь HTTP-статус будет 422, но он передаётся отдельно от JSON-тела. Валидатор выбрасывает ApiException, обработчик читает его статус/сообщение/подробности, создаёт ApiError, а Jackson сериализует публичные поля этого DTO в JSON.

## Что особенно важно не перепутать

- Внутренний id — первичный ключ БД. ИСУ — отдельное уникальное поле, используемое в адресах API. Изменение ИСУ не означает создание нового внутреннего id.
- Student — сущность БД; StudentDto — данные клиента. Конструктор DTO не выполняет запросов к БД: он только читает поля уже полученного объекта.
- Аннотации Swagger описывают API. Они сами не проверяют входные поля, JWT и роли. Реальная защита настроена в файлах безопасности вне этого списка.
- Проверка ИСУ в сервисе делает ошибку понятнее, а UNIQUE в БД защищает также от одновременных запросов. Одной предварительной проверки недостаточно.
- flush отправляет накопленные SQL-изменения в БД, commit окончательно закрепляет транзакцию, rollback отменяет её изменения. Это разные действия.
- По умолчанию @Transactional откатывает транзакцию при RuntimeException и Error, но не при любом checked exception. Наш ApiException наследует RuntimeException.
- Самостоятельный вызов private-метода внутри сервиса не начинает новую транзакцию. Он работает внутри уже открытой транзакции публичного действия сервиса.
- GET с пустыми фильтрами разрешён. Создание и изменение с пустым JSON-объектом валидатор отвергает.
- Фильтр списка isu=505 означает поиск по части ИСУ. Поле isu при создании студента должно быть полным шестизначным числом.
- Без page и size список не ограничен страницей. Если передать только size, включится page=0. Значение size=20 по умолчанию само по себе пагинацию не включает.
